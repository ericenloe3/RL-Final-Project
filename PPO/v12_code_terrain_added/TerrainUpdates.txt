How terrain was implemented
TerrainZone class (env.py)
A separate class from Obstacle because the two have fundamentally different physics: obstacles block movement via the collision system, while terrain zones are completely passable — only the parameters of movement change. The _rects_overlap static method already works on any object with .x .y .w .h, so TerrainZone objects plug straight in for spawn-overlap checks.
Mud mechanics
_resolve_terrain() returns (effective_action, effective_speed) before each move. For mud: action unchanged, speed → rated_speed × mud_slow (0.5×). No explicit reward penalty was added. The heading reward formula dot(displacement, to_prey) / rated_speed naturally produces half the reward in mud because actual displacement is halved — agents discover that mud is costly purely through the existing gradient. This lets them find the emergent strategic insight: mud equalizes the speed asymmetry (hunter is 4.5, prey 4.0), so the prey may actually want to lure the hunter into a mud patch.
Ice mechanics
When an agent's centre enters an ice zone after a step, _h_ice_action is set to the effective action that moved them in, and _h_on_ice = True. From the next step, _resolve_terrain() returns the frozen action and rated speed regardless of what action the policy outputs. When the centre exits, the flag clears. _last_act stores the effective action (not the requested one), so the policy's observation always reflects its actual heading — critical for ice because the policy needs to observe "I am moving in direction X against my will" to learn the situation.
Observation additions (obs_size 43 → 65)
Four status scalars per agent: own_in_mud, own_in_ice, other_in_mud, other_in_ice. The "other" status is strategically valuable — a hunter that sees p_on_ice=1 learns to close in hard since prey can't dodge; a prey that sees h_on_ice=1 learns to open distance. Plus K=3 nearest terrain zones encoded as (rel_cx, rel_cy, w, h, dist, type), type being 0.0=mud / 1.0=ice.
Curriculum (train.py)
Terrain is introduced late for three reasons: agents need solid obstacle navigation first (ice avoidance requires predicting multi-step consequences — that's impossible without a competent value function); the RunningNorm needs time to gather statistics on the 22 new dimensions before their gradient is reliable; and keeping difficulty gradual keeps the PPO clip ratio stable. Mud comes before ice (phase at 60%) because mud produces continuous gradients, while ice requires the policy to reason about actions it will take before entering a zone. Total steps raised 10M → 15M to give terrain phases enough exposure (if you're fine-tuning existing models, 6M extra steps from the checkpoint would also work). Prey entropy end-coefficient raised slightly (0.01 → 0.015) so the prey retains exploration capacity to discover ice-baiting strategies late in training.
Renderer (evaluate.py)
Terrain is drawn first (behind everything): a semi-transparent coloured pygame.Surface for the fill (brown for mud, pale blue for ice), then a solid border, then a small label. Agents gain an orange ring when on ice or yellow ring when in mud so you can visually track terrain state without reading the HUD. The HUD shows H:[ICE] / H:[MUD] status and the eval log records hunter_ice_steps and hunter_mud_steps per episode so you can measure how often agents interact with each zone type.
