What I deliberately kept simple (no new reward terms)
The temptation was to add shaping rewards like "prey bonus when hidden" or "hunter penalty when LOS blocked." I resisted those. The heading reward already does the job — if the prey keeps an obstacle between itself and the hunter, the hunter must detour, which delays capture, which means the prey gets more positive heading steps and more survival bonus. Emergent tactical play falls out of the existing reward; adding explicit LOS bonuses would create the same over-shaping problem that wrecked the earlier versions. The only new reward is a tiny -0.05 bump penalty per collision event, which is half the heading reward magnitude — it discourages pointless wall-grinding without making obstacles scary.
Physics: axis-separated sliding
Standard game-dev collision response. Try the full move; if it collides, try X-only; then Y-only; else stay. This means the hunter chasing prey along an obstacle edge doesn't freeze — it slides along the surface at reduced effective speed. The emergent consequence: the hunter's heading reward is highest when going straight at the prey, so it naturally learns to route around obstacles rather than grinding against them.
Observations: LOS + nearest-5 obstacles
The prey needs to know when it's hidden to learn tactical cover use, hence the line-of-sight bit. The nearest-5-obstacle features give both agents spatial awareness for navigation: each obstacle contributes rel-center-x, rel-center-y, width, height, and distance-to-surface, all normalized. Sorted nearest-first, zero-padded to a fixed slot count so the network input dimension stays constant regardless of actual obstacle count.
Curriculum: 0 → 1-3 → 3-6 obstacles
Phase 1 (first 30% of training, 1.5M steps, 0 obstacles) — the policies learn the exact same pursuit/evasion you already have working. Phase 2 (next 30%, 1-3 obstacles) introduces cover gradually. Phase 3 (final 40%, 3-6 obstacles) is full difficulty. This avoids catastrophic forgetting — you never throw a randomly-initialized policy into a 6-obstacle map and ask it to figure out everything at once.
What to expect behaviorally
The hunter should route around obstacles smoothly, losing minimal time to detours. The prey should figure out to break line-of-sight and keep obstacles between itself and the hunter — this is the tactically interesting behavior. Escapes (timeouts) should become more common in phase 3 as the prey gets better at hiding, bringing the capture rate down from ~100% (phase 1) to maybe 60-80%, which is healthy — an always-captured prey isn't playing well.
Minor knobs you can tune in env.py if you want easier/harder games: n_obstacles_range, obstacle_size_range, max_obstacles_obs (how many obstacles the policy sees in its observation). For more obstacles, bump HIDDEN in train.py from 128 to 256.
