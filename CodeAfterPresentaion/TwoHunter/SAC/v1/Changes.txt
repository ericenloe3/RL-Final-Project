Environment changes
Two-hunter geometry, one prey. step() now takes three actions (h1_action, h2_action, prey_action) and returns rewards keyed by hunter1, hunter2, prey. Either hunter reaching capture_dist of the prey ends the episode as a capture.
Equal speeds at 4.5 / 4.5. This is the most consequential balance change. In 1v1 the 4.5/4.0 speed advantage is what made eventual capture geometrically guaranteed — without it, a smart prey running in any straight line is uncatchable. In 2v1, the flanking advantage of two pursuers replaces that role: even with equal speeds, two coordinated hunters can pinch the prey from converging angles. Removing the speed gap prevents the contest from becoming trivially hunter-dominated and gives the prey a genuine path to learning evasion.
Episode length 500 → 600. With two hunters, naive captures should land much faster on average. The longer horizon ensures the prey has enough successful-evasion episodes to accumulate training signal from survival, rather than every episode ending in 50–100 steps before any cover-seeking pattern can develop.
Survival bonus 0.02 → 0.03. Compensates for the larger expected capture-penalty mass under 2v1. More episodes will end in capture early on, so the prey needs more positive per-step signal during the survival fragments to keep its return distribution from being entirely dominated by the −100 terminal.
Reward design for two hunters. Each hunter gets its own per-step heading/bump/search rewards independently. The prey heading reward averages escape components from both hunters: 0.1 × 0.5 × (escape_h1 + escape_h2). This is geometrically meaningful — maximum reward only when moving directly away from both hunters, which is only possible when the hunters are aligned behind the prey. When hunters flank, the average is reduced because the prey can only "half-escape," which is exactly the strategic dynamic we want to teach. LOS-break reward is split (0.25 per hunter) so the prey gets clean credit for breaking sight to one hunter even when the other still sees it. Capture reward is shared between both hunters regardless of who lands the catch — this prevents the two hunters from racing for the kill at the expense of coordination, since both get the same bonus either way.
Observation layout (50 features, identical across all three agents). Built around a fixed "primary other / secondary other" mapping: hunter1 sees prey as primary and hunter2 as secondary; hunter2 sees prey as primary and hunter1 as secondary; prey sees hunter1 as primary and hunter2 as secondary. The same shape across all three agents is essential for parameter sharing — and the prey's symmetric layout means it learns one consistent "threat-handling" sub-network rather than separate logic per hunter slot.
Training changes
Parameter-shared hunter network. This is the single most important architectural choice. One SAC actor and one critic are shared between hunter1 and hunter2. Each hunter is queried separately with its own observation to produce its own action, but their experiences pool into one replay buffer and gradients flow into one set of weights.
This matters for three reasons. First, identical roles mean identical optimal policy structure — separately parameterised hunters would have to relearn the same pursuit logic twice. Second, sharing eliminates the credit-assignment ambiguity where two distinct hunters might disagree on what makes a good hunter policy and degrade each other's training. Third, every env step adds two transitions to the hunter buffer, so the hunter network sees ~2× the data per environment step compared to the prey. This is appropriate because the prey already has the inherent advantage of "escaping" being easier than "catching" — the asymmetric data rate compensates by accelerating hunter convergence.
Both hunters frozen during 5% freeze. Random actions for both during the freeze window. Same rationale as 1v1: clean training distribution for the prey before the pursuit policy starts converging.
Curriculum simplified to obstacle-only. I removed the speed ramp (4.0 → 4.5) from the 1v1 SAC curriculum because speeds are now constant at 4.5/4.5 throughout. The obstacle ramp (0 → 1-3 → 3-6) does the difficulty work on its own.
v6 entropy fixes retained verbatim. ALPHA_FLOOR = 0.02 via softplus reparameterisation, target_entropy = 0.0 for both roles, α initialised at 0.2 (not 1.0), critic warmup of 5000 gradient steps, UTD = 0.25 (UPDATE_EVERY = 4). These were the load-bearing fixes that prevented α-collapse in 1v1, and there's no reason to reopen those questions just because we added a hunter — the entropy dynamics depend on action-space dimensionality and policy convergence behaviour, not on the number of agents.
Network capacity 192/192 (same as 1v1 v6). The hunter network is shared, so it has to encode both individual pursuit behaviour AND coordination patterns (e.g. "if my teammate is on the prey's left, I should approach from the right"). Same capacity as the prey is justified — possibly even understated, but I kept it at 192 to maintain comparability with the 1v1 results.
Tracking and logging. Capture rate is now decomposed per hunter: capture_h1 and capture_h2 show how often each hunter lands the actual catch. If these become very lopsided (e.g. h1 catches 80%, h2 catches 5%), it would suggest the parameter sharing is failing — both hunters should be contributing roughly equally. Per-agent returns are still logged separately so you can see if one hunter's return dwarfs the other's, which would also indicate a coordination failure.
Evaluation changes
The evaluator now loads the shared hunter checkpoint once and uses it for both hunter1 and hunter2 queries. Renderer draws hunter1 in dark blue and hunter2 in lighter blue so you can visually distinguish them in GIFs. HUD shows distance and LOS status to both hunters separately. Logs record both captured_by_h1 and captured_by_h2 flags, and los_breaks_h1 / los_breaks_h2 separately so you can see whether the prey is breaking sight to one hunter while still being tracked by the other.
