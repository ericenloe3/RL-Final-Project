The fix in four targeted changes
The diagnostic from the run logs pinpointed exactly when α collapsed: prey α dropped 1.0 → 0.005 in the first 200k steps (during the freeze, before the prey had even fully learned), and hunter α dropped to 0.05 within 130k steps after unfreeze. Capture rate peaked at 99.8% at 1.31M steps, then decayed monotonically as the prey co-evolved against an increasingly deterministic hunter that couldn't adapt. The fix targets the α dynamics at four points:
1. target_entropy raised from −1.0 to 0.0. This is the most important conceptual fix. SAC's α is a Lagrange multiplier whose sole purpose is keeping policy entropy at the target. When the target is set lower than what a "healthy" stochastic policy would have, α gets a continuous push-down gradient and collapses to zero — that's exactly what happened in v5. At target = 0.0, the gradient sign flips around action std 0.4–0.5, which is the operating point we actually want. The hyperparameter block has detailed reasoning for why 0.0 was chosen over −0.5 (still allowed slow drift) or +0.5 (actively pushed std up against natural reward-driven convergence).
2. Hard floor on α via softplus reparameterisation. Instead of using α = exp(log_alpha) directly, the v6 code uses α = ALPHA_FLOOR + softplus(log_alpha_param). This guarantees α ≥ 0.02 regardless of how negative log_alpha_param becomes. The floor is enforced by the parameterisation itself, not by post-hoc clipping, so the gradient w.r.t. log_alpha_param smoothly vanishes as the floor is approached rather than discontinuously zeroing. A get_alpha() helper is used everywhere α is read (target Q computation, actor loss, α loss, logging) for consistency. This is a defence-in-depth measure: even if the target-entropy choice turns out to need further tuning, α can never collapse to zero again.
3. UTD ratio reduced from 0.5 to 0.25. Off-policy methods with high update-to-data ratios are known to overcommit early — the critic gets very confident very fast on a small early-buffer distribution, and the actor follows it deterministically before the buffer has accumulated enough diverse transitions. UPDATE_EVERY going from 2 to 4 halves the gradient steps per environment step, giving the buffer time to refresh. This is a smaller intervention than the entropy fixes but addresses a separate accelerant of the collapse.
4. Critic warmup of 5000 gradient steps. The very first actor + α updates after LEARNING_STARTS use a near-random Q function, which produces wildly inaccurate gradients. With target_entropy = -1, those gradients pushed α down so fast that the system was already in trouble before the critic learned anything useful. The warmup runs only critic updates for the first 5000 gradient steps; the actor and α stay frozen during this window so neither receives noise-dominated updates. The hunter's warmup counter is also reset on its unfreeze (when its replay buffer is cleared) so it gets a fresh warmup period against its rebuilt buffer.
What the new console output looks like
Each per-agent log line now shows live entropy alongside α:
hunter: ret  +85.2  α=0.067  H_live=+0.12 (target +0.0)  buf=950,000
prey:   ret  -45.1  α=0.034  H_live=-0.18 (target +0.0)  buf=950,000  [warmup]
*FLR* flags α at the floor; [warmup] flags an agent in the critic-warmup phase. H_live is the actual policy entropy on a sample batch — at convergence it should sit near target (0.0), indicating the auto-tuner is doing its job.
What you should see in the next run
α should stabilise in the 0.05–0.15 range rather than collapsing to 0.005. Live entropy should track the target (0.0) within ±0.3. Capture rate should not show the early peak followed by regression that v5 produced — instead a slower climb that holds. If α saturates against the floor for extended periods (*FLR* flag persistent), that's a signal the target needs to be raised further. If α blows up above 1.0, the target is too high. The diagnostics now make it possible to tell which is happening.
If after a v6 run there's still a problem, the next thing I'd consider is making the SAC actor's log_std_head more bounded — its current [-20, 2] range allows the same mean-policy-becomes-noise failure that PPO's log_std had, just less acutely because SAC samples through reparameterisation.
